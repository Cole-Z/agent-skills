# Usage-aware

Helps decide what can realistically be finished with the usage that's left, and leaves a clean handoff so nothing is lost or redone.

## Steps
1. **Check real usage first.** Read the current plan usage (percent used, reset time, extra credits). Never guess the numbers.
2. **List the open work.** Pull the active tasks from the todo list and recent conversation. For each one, note what's done, what's left, and its rough cost.
3. **Estimate cost honestly, and label it as an estimate.**
   - Small: quick answers, a single lookup or edit.
   - Medium: a short research pass, a small PR, a few tool rounds.
   - Large: multi-step builds, long research, browser automation, repeated CI loops.
4. **Triage.** Sort the work into three groups:
   - **Do now:** small, urgent, or blocking.
   - **Do if room:** medium items, in order of value.
   - **Defer to the reset:** large or non-urgent.
   Recommend the smallest useful version of anything big.
5. **Cut waste.** Pause non-essential routines and checkups, avoid open-ended research and duplicate work, and keep replies short.
6. **Write a checkpoint before stopping.** For each deferred item, record the goal, the current state (links, PRs, IDs, file paths), the exact next step, and any decisions already made. Save it somewhere durable (memory, a todo list, or a notes file) so work resumes without backtracking.
7. **Report briefly.** Give usage left and the reset time, what will get done now, what's deferred, and where the checkpoint lives. Ask only if the priority order is unclear.

## Rules
- Never fabricate usage numbers or claim work is done when it isn't.
- Prefer finishing one thing over half-starting several.
- When unsure whether something fits, say so and propose the smaller option.
